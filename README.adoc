= Smartmii Fan Control
:toc: macro
:toclevels: 2
:icons: font

LoxBerry plugin for controlling Smartmi Standing Fan 3 (zhimi.fan.za5) devices via Xiaomi Cloud API and MQTT.

toc::[]

== Overview

Smartmii connects your Smartmi Standing Fan 3 to your Loxone Miniserver through LoxBerry's MQTT gateway.
The plugin communicates with the fans through the Xiaomi Cloud API, publishes device status to MQTT topics, and accepts commands via MQTT -- enabling full integration with Loxone Config.

=== Features

* Control multiple Smartmi fans from a single LoxBerry instance
* Cloud-based communication (no local network restrictions)
* Automatic device discovery via Xiaomi Cloud
* Retained MQTT messages for reliable state synchronization
* Downloadable Loxone Config XML template for quick setup
* Hot-reload of configuration (no daemon restart needed)
* Integrated LoxBerry logging with configurable log levels

== Prerequisites

* **LoxBerry 3.0** or newer
* **Xiaomi / Mi Home account** with your fans registered
* **MQTT broker** (built into LoxBerry)
* Fan model: **Smartmi Standing Fan 3** (`zhimi.fan.za5`)

== Installation

. Open your LoxBerry web interface
. Navigate to **Plugin Management**
. Click **Add Plugin** and enter the GitHub repository URL:
+
----
https://github.com/wkulhane/loxone-smartmii
----
. Click **Install**

The installer automatically creates a Python virtual environment and installs the required dependencies (`paho-mqtt`, `requests`, `pycryptodome`).

== Configuration

=== Step 1: Xiaomi Cloud Login

. Open the plugin web UI (LoxBerry > Plugins > Smartmii Fan Control)
. Expand the **Xiaomi Cloud Login** section
. Select your **server region** (e.g. `de` for Germany)
. Enter your Xiaomi account **email** and **password**
. Click **Login**

The login process is multi-step:

. **Captcha** -- Xiaomi shows a captcha image. Enter the code and click Submit.
. **2FA** -- A verification code is sent to your email. Enter it and click Submit.
. On success, the session is saved to disk. You do not need to log in again unless the session expires.

=== Step 2: Add Fans

The easiest way to add fans is via device discovery:

. Click **Discover Devices** in the Fans section
. A list of all devices on your Xiaomi account appears
. Click the **+** button next to each fan you want to add
. The fan is added to your configuration with its name and Device ID (DID)

Alternatively, add fans manually by clicking **Add Fan** and entering the device name and DID.

=== Step 3: Settings

[cols="1,1,3"]
|===
| Setting | Default | Description

| MQTT Prefix
| `smartmii`
| Prefix for all MQTT topics

| Poll Interval
| `30`
| Seconds between status polls (5-300)

| Server Region
| `de`
| Xiaomi Cloud server (cn, de, us, ru, tw, sg, in, i2)
|===

Click **Save Settings** after making changes.

=== Step 4: Start the Daemon

Click **Restart** in the daemon control section. The daemon connects to the MQTT broker and begins polling your fans.

== Pitfalls and Known Issues

Xiaomi rate-limits verification codes::
If you trigger too many captcha or 2FA attempts in a single day, Xiaomi stops sending verification codes. You must **wait approximately 24 hours** before trying again. Avoid repeatedly clicking "Login" if the captcha fails -- double-check the code carefully before submitting.

Session expiration::
The Xiaomi Cloud session can expire after an extended period. When this happens, the daemon logs an error and exits. You must re-login via the web UI. The daemon cannot re-authenticate automatically because the login requires interactive captcha and 2FA.

Cloud API latency::
Commands sent via the cloud take 1-2 seconds to reach the fan (compared to instant local control). Status updates are only as current as the last poll interval.

Fan must be registered in Mi Home::
The fan must be added to your Mi Home app and associated with your Xiaomi account before the plugin can discover or control it.

== MQTT Reference

All topics use retained messages. The default prefix is `smartmii`.

=== Status Topics (read-only)

Published by the daemon every poll interval.

Topic pattern: `{prefix}/{fan_id}/status/{property}`

[cols="1,1,1,2"]
|===
| Property | Type | Range | Description

| `power`
| Binary
| 0 / 1
| Power state

| `fan_level`
| Integer
| 1-4
| Fan speed level

| `oscillate`
| Binary
| 0 / 1
| Oscillation (horizontal swing) on/off

| `angle`
| Integer
| 30 / 60 / 90 / 120
| Oscillation angle (degrees)

| `mode`
| Integer
| 0 / 1
| 0 = natural, 1 = straight wind

| `buzzer`
| Binary
| 0 / 1
| Button sound feedback

| `online`
| Binary
| 0 / 1
| Device reachable via cloud
|===

=== Command Topics (write)

Publish a value to control the fan. The daemon re-polls the fan after each command.

Topic pattern: `{prefix}/{fan_id}/cmd/{command}`

[cols="1,2,2"]
|===
| Command | Accepted Values | Notes

| `power`
| on / off / 1 / 0 / toggle
| `toggle` inverts the current state

| `fan_level`
| 1-4
| Clamped to valid range

| `oscillate`
| on / off / 1 / 0
| Horizontal swing

| `angle`
| 30 / 60 / 90 / 120
| Invalid values are rejected

| `mode`
| straight / natural / 0 / 1
| 0 = natural, 1 = straight

| `buzzer`
| on / off / 1 / 0
|
|===

=== Daemon Status

[cols="1,2"]
|===
| Topic | Values

| `{prefix}/daemon/status`
| `online` when running, `offline` on shutdown (will message)
|===

=== Examples

Turn on the office fan:
----
mosquitto_pub -t "smartmii/buero/cmd/power" -m "on"
----

Set fan level to 3:
----
mosquitto_pub -t "smartmii/buero/cmd/fan_level" -m "3"
----

Monitor all status updates:
----
mosquitto_sub -t "smartmii/#" -v
----

== Loxone Config Integration

The plugin can generate an XML template for importing Virtual Inputs into Loxone Config.

=== Download the XML Template

. Open the plugin web UI
. Expand the **MQTT Topics** section at the bottom
. Click the **VI_MQTT_UDP_Smartmii.xml** button
. Save the downloaded file

=== Import into Loxone Config

. Open **Loxone Config**
. Navigate to **Periphery** in the left panel
. Right-click **Virtual Inputs** and select **Import**
. Select the downloaded `VI_MQTT_UDP_Smartmii.xml` file
. A new Virtual Input named "Smartmii Fans (MQTT UDP)" appears with entries for each fan property

The template uses **port 11883** (LoxBerry MQTT Gateway UDP port). Each configured fan gets entries for: power, fan_level, oscillate, angle, mode, buzzer, and online.

=== Using the Virtual Inputs

After import, drag the Virtual Input entries you need into your Loxone project:

* **Power** (0/1) -- connect to a switch or status indicator
* **Fan Level** (1-4) -- connect to a status display or visualization
* **Online** (0/1) -- use for monitoring and alerts

To send commands to the fans, create Virtual Outputs manually in Loxone Config that publish to the `{prefix}/{fan_id}/cmd/{command}` MQTT topics.

== Logging

The plugin integrates with LoxBerry's logging system. The log level can be configured in **LoxBerry > System > Plugin Management** (dropdown next to the Smartmii plugin).

=== Log Levels

[cols="1,1,3"]
|===
| Level | Name | What is logged

| 7
| Debug
| Every cloud API request/response, MQTT messages, poll results, property values

| 6
| Info
| Login attempts, device discovery, daemon start/stop, commands sent

| 5
| OK
| Same as Info

| 4
| Warning
| MQTT disconnects, poll failures, unknown commands

| 3
| Error
| Cloud API failures, login errors, config errors

| 0
| Off
| Logging disabled
|===

=== Log Files

All components write to the same log file at `LBPLOGDIR/smartmii.log` (typically `/opt/loxberry/log/plugins/smartmii/smartmii.log`). The file rotates at 1 MB with 3 backups.

Web UI actions (login, config saves, daemon control) are additionally registered in LoxBerry's Log Manager and visible under **LoxBerry > System > Log Manager**.

=== Development / Testing

When running outside of LoxBerry, use the `--loglevel` flag:

----
python3 bin/smartmii_daemon.py --configdir ./config --logdir ./log --loglevel DEBUG
----

== Uninstall

When uninstalled through LoxBerry Plugin Management:

. The daemon is stopped
. All retained MQTT messages are cleared (requires `mosquitto_pub`)
. Plugin files are removed
